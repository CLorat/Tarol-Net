# Probes: Scheduled jobs (step 14 design)

Evidence for [docs/migration/jobs.md](../../jobs.md) and [docs/architecture/jobs.md](../../../architecture/jobs.md).
The probe is copied and adapted, never referenced, and stays out of `Tarol.slnx`. `*.csproj.txt` becomes a project file in a
work directory (`run.sh`); `TarolRoot` points at this repository, so the probe builds against **today's** packages
(`Tarol.Persistence.Npgsql`, `Tarol.Changes`, `Tarol.Sagas`, the Changes and Primitives generators). Nothing in it is package code.

| File | What it is |
|---|---|
| `Jobs/Scheduler.cs` | the would-be runtime: `IJobRows` (a schedule row per (tenant, job): the cursor `next_at`, a claim id and a lease), `NpgsqlJobRows` (variant **A**: `FOR UPDATE SKIP LOCKED` claims), `LeaderJobRows` + `Leader` (variant **B**: one leader by `pg_try_advisory_lock`), `InMemoryJobRows` (the test helper's rows), `JobRunner` (claim → pick the occurrences by the missed-run policy → run each with the occurrence key → move the cursor after each → advance; heartbeat at lease/3; retry with backoff; give up after `MaxAttempts`) |
| `Jobs/Cron.cs` | `ISchedule`: `CronosSchedule` (Cronos 0.12.0), `MiniCron` (a 5-field parser of our own, ~130 lines), `IntervalSchedule` (no cron) |
| `Jobs/Domain.cs` | `Tally` (what a job changes: one `Recorded(occurrence)` per committed run), `Schedule` (variant **D**: an aggregate whose `Due(at)` events are scheduled reactions `RunScheduled` and `AdvanceSchedule`, generated by today's Changes generator), `AckPing` (a reaction backlog) |
| `Jobs/Worker.cs` | a worker process of the chaos runs (A, A without the key, B, D); `PROBE_CRASH_EVERY`, `PROBE_WORK_MS`, `PROBE_LEASE_MS`, `PROBE_POLL_MS`, `PROBE_BATCH` |
| `Jobs/Chaos.cs` | the orchestrator: N worker processes, `kill -9` and `SIGSTOP` 2–6 s of a random one every 1.5–3 s, restarts; then counts per occurrence: commits (events), attempted runs (`runs` table), lateness |
| `Jobs/SelfTest.cs` | `selftest cron` (DST table, Cronos vs ours over 2 years × 3 zones), `test` (FakeTimeProvider + in-memory store: the `JobTest` story), `postgres` (A, B, D on the store) |
| `Jobs/Bench.cs` | `bench cron`, `claim`, `tenants <n>`, `backlog <n>`, `lease` |
| `inventory.md` | the old code (`CLorat/Tarol@6a62f81`) and what Tarol-Net already has, file:line |
| `output.txt` | the last `all.sh` run (sections 0–10) |

```bash
dockerd > /tmp/dockerd.log 2>&1 &                 # postgres:17 (tarol-probe-pg, 55432); all.sh starts it
docs/migration/probes/jobs/all.sh /tmp/j           # resumable: sec-<n>.txt + .ok per section; ALL_REDO=<n> redoes one
docs/migration/probes/jobs/run.sh /tmp/w Jobs run -c Release -- selftest postgres      # one run; PROBE_PG overrides the database
docs/migration/probes/jobs/run.sh /tmp/w Jobs run -c Release -- chaos A 60 3 10 both 25
```

Notes:
* The chaos jobs fire every second (an `IntervalSchedule`), so a 60 s window has 61 occurrences per job; with 10 jobs, 610 per run.
* "Duplicate commits" counts occurrences with more than one `Recorded` event; "duplicate runs" counts occurrences whose body
  started more than once (logged before the change, outside its transaction).
* Never run `all.sh` next to the full test suite: sections 4–10 measure latency and throughput on the same 4 cores.
